# SDK bump — claude-agent-sdk 0.1.59 → 0.2.88

> Point-in-time snapshot (2026-06-03). Not maintained. See `CARDS/` for living docs.

## What & why

`requirements.txt` pinned `claude-agent-sdk>=0.1.59`. The floor allowed installs
from the stale `0.1.x` series. We bumped the floor to `>=0.2.88` (latest on PyPI).

This matters for **cost reporting**: the dashboard never computes prices from
per-token rates — it reads `total_cost_usd` straight from the SDK
(`src/agent/session.py`). There are **no hardcoded price tables anywhere in the
repo**, so token pricing stays correct only as long as the SDK floor is current.
The thing to keep up to date is the SDK version, not a rate table.

- Bump commit: `c783305` (`requirements.txt:5`), merged to `main`.
- Full suite (1063 tests) passes on 0.2.88.

## Notable SDK changes across the range

### Breaking (introduced at 0.2.0 — already absorbed; tests pass)
- `ClaudeCodeOptions` → **`ClaudeAgentOptions`** (rename). We already use the new name.
- `custom_system_prompt` + `append_system_prompt` merged into **`system_prompt`**.
- Claude Code system prompt no longer default → opt in via
  `system_prompt={"type":"preset","preset":"claude_code"}`.
- Filesystem settings / `CLAUDE.md` / subagents no longer loaded by default →
  opt in via `setting_sources=["user","project","local"]`. We pass
  `setting_sources=["project"]` already.

### New features we adopted (see "What was done")
- **`ResultMessage.api_error_status`** (0.1.74) — HTTP status (429/500/529) of a
  failing API call; safe-to-log classifier for API vs. agent/task errors.
- **`ServerToolUseBlock` / `ServerToolResultBlock`** (0.1.65) — server-executed
  tool calls (advisor, web_search) and their results. Previously *silently
  dropped*, so advisor-only messages arrived as empty `AssistantMessage`.

### New features available but NOT yet adopted
- File checkpointing + `rewind_files()` (`enable_file_checkpointing`) — natural
  fit for the review→reject flow (revert an agent's changes to a checkpoint).
- Session forking / `SessionStore` adapters (`fork_session`, `delete_session`,
  S3/Redis/Postgres) — could back "copy agent" / persistent resume.
- Thinking display control (`display` on `ThinkingConfig`) — we run a 32k thinking
  budget; this can surface *summarized* thinking text for the UI.
- Hook event streaming (`include_hook_events` → `HookEventMessage`) — richer
  per-agent activity timeline.
- `task_budget` (token cap per task), `strict_mcp_config`, `xhigh` effort level.

0.2.83–0.2.88 are almost entirely bundled Claude CLI bumps (2.1.142 → 2.1.161)
plus trio-compat and stderr-callback fixes — no new API surface.

## What was done

Edits in `src/agent/session.py`:

1. **`api_error_status` surfaced** — added `api_error_status: int | None` to the
   `AgentResult` dataclass; the `ResultMessage` handler reads it (guarded to a
   real `int`) and prefixes errored runs as `[HTTP <status>] <message>`.
2. **Server tool blocks un-dropped** — imported `ServerToolUseBlock` /
   `ServerToolResultBlock`; the receive loop now routes `ServerToolUseBlock` to
   `on_tool_use` (advisor/web_search shows in the activity feed) and flattens
   `ServerToolResultBlock` via new `_server_result_text()` into an `[advisor] …`
   message via `on_message`.

### 2026-10-14 — floor `>=0.2.88` → `>=0.2.165`

0.2.88 was ~76 releases stale (and is no longer even listed on PyPI). New floor
is `>=0.2.165`, the latest release. Also updated the two docs that state the
floor: `README.md` (tech stack) and `AGENT_FILES/README.md` (root-file index).

- **Full suite: 1321 passed, 1 skipped** on a clean venv resolving 0.2.165
  (`mcp` 1.30.0). The skip is the pre-existing environmental one —
  `test_graph_service.py` needs `graphifyy` installed.
- **No code changes were needed.**

Changelog review, 0.2.89 → 0.2.165 — the "almost entirely bundled Claude CLI
bumps" character still holds (CLI 2.1.162 → 2.1.294), with two entries that
needed checking and one bug fix worth knowing about:

- **0.2.129 (the only "Breaking Changes" heading in the range)** — skill names
  in `ClaudeAgentOptions.skills` are now validated and raise `ValueError`;
  `skills=["*"]` must become `skills="all"`. **Does not affect us**: we never
  pass `skills=`, because dashboard-managed Agent Skills are delivered as
  one-skill plugins through `plugins=` (see `CARDS/SKILLS.md`).
- **0.2.137** — the `Message` union widened (`ConversationResetMessage`), which
  breaks exhaustive matches. **Does not affect us**: no `assert_never` anywhere
  in `src/`; the receive loops in `session.py` / `review_agent.py` match the
  types they care about and ignore the rest.
- **0.2.160 (a real win for this project)** — fixed stdin closing too early when
  a background subagent finished just before the turn's result, which made
  follow-up turns fail with "Stream closed" and the model report the tool as
  refused. It only bit sessions using hooks, `can_use_tool`, or SDK MCP servers
  — i.e. every dashboard agent. Related earlier fixes: 0.2.127 (same class, for
  `run_in_background` subagents), 0.2.111 (zombie `claude` subprocesses on
  cancellation, plus silent whitespace loss on NDJSON lines over 64 KiB).

New API surface available but still **not** adopted (on top of the 0.2.88-era
list above): `ResultError` with a structured payload instead of a bare exit-code
error, `ResultMessage.terminal_reason` (distinguishes an `interrupt()` from a
normal finish — relevant to pause/resume), typed `ResultMessage.model_usage`,
`verbatim_prompts` (no `@path` expansion or slash-command dispatch in a prompt —
worth considering for untrusted text in item descriptions),
`forward_subagent_text`, `resume_session_at` / `resume_drops_turn`, and
`mcp` 2.x support for in-process SDK MCP servers.

### 2026-10-14 (later the same day) — `verbatim_prompts` adopted

`verbatim_prompts` has moved off the "not adopted" list above: it is now
`True` at all three `ClaudeAgentOptions` call sites (`src/agent/session.py`,
and both branches of `src/agent/review_agent.py`). Everything else in that
list is still unadopted.

Why: the dashboard builds its prompts out of board-item text — title,
description, the implementing agent's last message, and the raw diff. With the
default (`False`) the CLI treats that text as input to interpret: an `@path`
anywhere in it is expanded into a file read before the model sees the prompt,
and a leading `/name` is dispatched as a slash command. A description reading
`check @../../id_rsa` was an unintended file read, not an instruction.

Checked before flipping it:
- **Nothing relies on `@path` expansion.** Attachments are listed as plain
  absolute paths with "use Read tool to view" (`build_attachment_prompt`), the
  shared plan is injected as text, and no prompt builder emits `@`-prefixed
  references. No prompt is meant as a slash command either — the dashboard
  chat passes follow-up text straight to `client.query()`.
- **The Ollama profile is unaffected.** `verbatim_prompts` is a CLI-level
  flag, not a model one, so it composes with the profile's `thinking` /
  `setting_sources` overrides; both the session and the reviewer's Ollama
  branch set it.
- **No version gate.** The flag needs CLI 2.1.248+ and our floor bundles
  2.1.294. On an older CLI the SDK only logs a warning, so a hard assert would
  turn a benign degradation into a crash — deliberately not added.

Suite after the change: **1326 passed, 1 skipped** (same environmental
`graphifyy` skip), including 5 new tests — 2 in `tests/unit/test_session.py`
and a new `tests/unit/test_review_agent.py` (3).
